## 1.2 重点内容

### 1.2.1 背景：为什么做这个项目

**机械臂**是工业与科研中最常见的机器人形态。你想让它抓一个杯子，需要解决三件事：

1. **它长什么样** —— 有几节臂、每节多长多重、关节能转多少度 → **模型（URDF）** 解决；
2. **它该怎么动** —— 从当前位置到目标位置，每个关节按什么角度序列运动、路上不能撞到自己 → **运动规划（MoveIt 2）** 解决；
3. **指令怎么送到电机** —— 软件算出的角度如何变成电机的转动 → **控制（ros2_control）** 解决。

真机开发很贵：机械臂要钱、撞坏了要修、调试一次要很久。所以工业界和学术界都先用**仿真**跑通全部软件逻辑，再上真机。本项目的全部工作都在仿真里完成。

**为什么选 ROS 2 这套技术栈**：它是机器人领域事实上的标准，社区资料多、仿真/规划/控制组件齐全，学会它等于拿到了这个领域的通用语言。

### 1.2.2 八个必须记住的基础概念

| 概念 | 通俗解释 | 本项目中的例子 |
|------|---------|--------------|
| **节点 Node** | 一个独立运行的小程序，只干一件事 | 规划器 `move_group`、状态发布器 `robot_state_publisher` 各是一个节点 |
| **话题 Topic** | 一对多的广播频道，发布者不停广播，订阅者各自收取 | `/joint_states` 广播每个关节的当前角度 |
| **服务 Service** | 一问一答的调用（有请求有响应，会阻塞） | 控制器加载时的 `/controller_manager/load_controller` |
| **动作 Action** | 长时间任务的"带进度反馈的调用"，可取消 | MoveIt 把轨迹发给 `/ros2_arm_controller/follow_joint_trajectory` |
| **参数 Parameter** | 节点的配置项，运行时也可改 | 控制器 YAML 里的 `update_rate` |
| **launch 文件** | 用代码描述"一次启动要同时跑哪些节点、带什么参数" | `gz_launch.py` 一口气启动 8 个东西 |
| **包 Package** | ROS 2 的代码组织单位，一个包一个目录 | `ros2_arm_description` |
| **工作空间 Workspace** | 存放若干包的目录，统一用 colcon 编译 | `/home/lichaoming/ros2_arm` |

**补充两个高频词**：

- **TF（Transform）**：ROS 2 里专门管理"坐标系之间相对位置关系"的机制。比如"link2 的坐标系相对于 link1 的坐标系，现在转了 30 度、向上偏移 0.05 米"。RViz 显示机械臂靠的就是 TF 树。
- **仿真时间 /sim time**：仿真里的时间由 Gazebo 通过 `/clock` 话题广播。所有节点统一用仿真时钟，时间戳才能对上；启动节点时要传 `use_sim_time:=True`。

### 1.2.3 三个"专业名词"的大白话版本

1. **自由度（DOF, Degree of Freedom）**：机械臂能独立运动的关节数量。3 个转动关节 = 3 自由度。自由度越多越灵活，但规划越难——所以我们从 3 个开始，原型 akabot 是 6 个。
2. **正运动学 / 逆运动学**：
   - 正运动学：知道每个关节角度 → 算出末端在哪（唯一答案，简单）；
   - 逆运动学（IK）：知道末端要去哪 → 反推关节角度（可能有多个解，也可能无解，难）。
   MoveIt 的核心工作之一就是解 IK。**你不需要自己写数学公式**，MoveIt 内置了求解器插件（本项目用 `kdl_kinematics_plugin`）。
3. **硬件接口（Hardware Interface）**：ros2_control 在"上层软件"和"底层硬件"之间定义的统一约定——上层只管说"把 joint2 转到 0.5 弧度"，至于底层是仿真引擎还是真实电路板，它不关心。这个抽象是**同一个项目能一键切换仿真/真机**的根本原因。

### 1.2.4 项目目标与分阶段验收

| 阶段 | 目标 | 过关标准（可自查） |
|------|------|------------------|
| 阶段 0 环境 | 工具链装好 | `ros2 --version`、`ign gazebo --version`、`ros2 pkg list \| grep moveit` 都有输出 |
| 阶段 1 建模 | 机械臂模型能在 RViz 里显示并手动摆关节 | `display.launch.py` 打开 RViz，拖动滑块模型跟着动 |
| 阶段 2 仿真 | 机械臂出现在 Gazebo 里，控制器激活 | `ros2 control list_controllers` 三个控制器都是 `active` |
| 阶段 3 控制 | 能命令机械臂去指定角度 | 发一条轨迹，关节真的转过去 |
| 阶段 4 规划 | MoveIt 能自己算路径并执行 | RViz 里点 Plan & Execute 机械臂动起来 |
| 阶段 5 收尾 | 项目结构清晰、有笔记、能讲清楚 | 你能给同学讲一遍"一条指令的旅程" |

### 1.2.5 学习心态提示

- **报错是常态，不是失败**。ROS 2 项目的第一次启动几乎不可能一次成功，报错信息通常会告诉你原因。
- **不要跳章**。第 05 章没做完就去做第 07 章，一定会卡在"找不到模型文件"。
- **一次只改一处**。改完就验证，改坏就改回来——这是唯一能建立因果直觉的方法。

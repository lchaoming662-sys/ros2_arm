# 第 07 章 仿真环境详解（Gazebo Fortress）

> 本章让机械臂"出现在一个世界里"。三个文件：世界文件、话题桥、启动文件。
> 做完本章，你的机械臂就会站在虚拟地面上，并且能听控制器的指挥。

## 7.2 重点内容（一）：Gazebo Fortress 的基本概念

| 概念 | 含义 | 类比 |
|------|------|------|
| **World 世界** | 一个场景文件：物理参数、光照、地面、里面的物体 | 一个"关卡" |
| **Model 模型** | 世界里的一件东西（可以是机械臂，也可以是桌子） | 关卡里的"角色" |
| **Link / Joint** | 与 URDF 里同样的概念，SDF 格式里也有 | 同 URDF |
| **Plugin 插件** | 挂进仿真器内部、扩展功能的动态库 | 给引擎装的"模块" |
| **System** | Fortress 里的插件统称（物理、渲染、传感器…） | — |

**关键区别：URDF vs SDF**

| | URDF | SDF |
|---|------|-----|
| 用途 | ROS 侧描述"一个机器人" | Gazebo 侧描述"整个世界" |
| 能否描述世界 | 不能（没有地面、光照概念） | 能 |
| 谁生成谁 | — | Gazebo 内部把 URDF **转换**成 SDF 再加载 |

所以流程是：你写 URDF 描述机械臂 → Gazebo 自动转换 → 你另外写一个 SDF 世界文件提供"舞台"。

**Fortress 的版本别名坑**：Gazebo 从 "Ignition" 改名为 "Gazebo" 的过程中留下大量双名（`ign gazebo` = `gz sim`，`ignition.msgs.Clock` = `gz.msgs.Clock`，`ign_ros2_control` = `gz_ros2_control`）。**看到 ign 前缀不要慌，那只是历史遗留**。

## 7.3 重点内容（二）：世界文件 `arm_world.sdf`

> 写到 `src/ros2_arm_gazebo/worlds/arm_world.sdf`

```xml
<?xml version="1.0" ?>
<!-- ============================================================
     arm_world.sdf
     作用：为 ros2_arm 提供一个带地面、光照、物理参数的虚拟世界
     ============================================================ -->
<sdf version="1.8">
  <world name="arm_world">

    <!-- ---------- 1. 物理引擎参数 ---------- -->
    <physics name="1ms" type="ignored">
      <max_step_size>0.001</max_step_size>   <!-- 每步 1 ms -->
      <real_time_factor>1.0</real_time_factor><!-- 尽量与真实时间同速 -->
    </physics>

    <!-- ---------- 2. 必备的系统插件（少了仿真就不工作） ---------- -->
    <plugin filename="ignition-gazebo-physics-system"
            name="ignition::gazebo::systems::Physics"/>
    <plugin filename="ignition-gazebo-user-commands-system"
            name="ignition::gazebo::systems::UserCommands"/>
    <plugin filename="ignition-gazebo-scene-broadcaster-system"
            name="ignition::gazebo::systems::SceneBroadcaster"/>

    <!-- ---------- 3. 光照 ---------- -->
    <light type="directional" name="sun">
      <cast_shadows>true</cast_shadows>
      <pose>0 0 10 0 0 0</pose>
      <diffuse>0.8 0.8 0.8 1</diffuse>
      <specular>0.2 0.2 0.2 1</specular>
      <direction>-0.5 0.1 -0.9</direction>
    </light>

    <!-- ---------- 4. 地面 ---------- -->
    <model name="ground_plane">
      <static>true</static>
      <link name="link">
        <collision name="collision">
          <geometry>
            <plane><normal>0 0 1</normal><size>20 20</size></plane>
          </geometry>
        </collision>
        <visual name="visual">
          <geometry>
            <plane><normal>0 0 1</normal><size>20 20</size></plane>
          </geometry>
          <material>
            <ambient>0.75 0.75 0.75 1</ambient>
            <diffuse>0.75 0.75 0.75 1</diffuse>
          </material>
        </visual>
      </link>
    </model>

    <!-- ---------- 5. 一个练习用的方块（第 08 章可以试着去"够"它） ---------- -->
    <model name="target_cube">
      <static>true</static>
      <pose>0.32 0 0.03 0 0 0</pose>
      <link name="link">
        <collision name="collision">
          <geometry><box><size>0.06 0.06 0.06</size></box></geometry>
        </collision>
        <visual name="visual">
          <geometry><box><size>0.06 0.06 0.06</size></box></geometry>
          <material>
            <ambient>0.2 0.6 0.9 1</ambient>
            <diffuse>0.2 0.6 0.9 1</diffuse>
          </material>
        </visual>
      </link>
    </model>

  </world>
</sdf>
```

**逐段说明**：

| 段落 | 要点 |
|------|------|
| 1. physics | `max_step_size=0.001`（1 ms）是常用值；步长越小越准但越慢。注意控制器配置里 `update_rate: 100`（10 ms）比它慢，会有个告警，属正常 |
| 2. plugins | **三件套缺一不可**：Physics 负责物理、UserCommands 负责响应"生成模型"的请求、SceneBroadcaster 负责把场景推给 GUI。少一个会出现"命令没反应"或"GUI 空白" |
| 3. light | 没有光照，GUI 里是**一片漆黑**（但模型是存在的，别误判成失败） |
| 4. ground_plane | `static=true` 表示无限重量的固定物体，不会掉下去 |
| 5. target_cube | 一个静止的方块，纯装饰，方便你直观感受"机械臂够不够得到" |

**想加更复杂的东西**（桌子、相机、多物体）：可以参考原型的 `akabot_gazebo/worlds/pick_and_place.world`，那是"多物体 + 相机"的完整例子，结构与本文件一致，只是模型更多。

## 7.4 重点内容（三）：话题桥 `ros2_arm_bridge.yaml`

> 写到 `src/ros2_arm_gazebo/config/ros2_arm_bridge.yaml`

**为什么需要桥**：Gazebo 内部用自己的一套消息（`gz.msgs.*`），ROS 2 节点听不懂。`ros_gz_bridge` 的 `parameter_bridge` 节点充当**同声传译**：把 Gazebo 话题翻译成 ROS 话题（或反向）。

```yaml
# ============================================================
# ros2_arm_bridge.yaml
# 由 parameter_bridge 读取：定义"哪些 gz 话题 ↔ 哪些 ROS 话题"
# ============================================================

# 仿真时钟：Gazebo 的时间基准，所有开了 use_sim_time 的节点都要它
- ros_topic_name: "clock"
  gz_topic_name: "clock"
  ros_type_name: "rosgraph_msgs/msg/Clock"
  gz_type_name: "gz.msgs.Clock"
  direction: GZ_TO_ROS
```

**四个字段的含义**：

| 字段 | 说明 |
|------|------|
| `ros_topic_name` | ROS 2 侧的话题名（注意：**不要写开头的 `/`**） |
| `gz_topic_name` | Gazebo 侧的话题名 |
| `ros_type_name` / `gz_type_name` | 两侧的消息类型，必须一一对应 |
| `direction` | `GZ_TO_ROS`（仿真→ROS）、`ROS_TO_GZ`（ROS→仿真）、`BIDIRECTIONAL`（双向） |

**本项目只需要桥接 `clock`**，原因：
- 关节状态**不走桥**——它由 ros2_control 插件直接以 ROS 消息发布（`/joint_states`）；
- 你的机械臂暂时没有相机和雷达，没有图像/点云要桥接。

以后想加相机，就往这个文件里追一条（参考原型 `akabot_bridge.yaml` 里 `camera/camera_info` 那几条的写法）。

## 7.5 重点内容（四）：启动文件 `gz_launch.py`

> 写到 `src/ros2_arm_gazebo/launch/gz_launch.py`

launch 文件就是"把手动敲的一串命令固化成代码"。本文件一次启动 7 件事。

```python
"""启动 ros2_arm 的完整仿真环境：Gazebo + 模型 + 桥 + 三个控制器。"""
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import (DeclareLaunchArgument, IncludeLaunchDescription,
                            TimerAction)
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import Command, LaunchConfiguration
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    pkg_desc = get_package_share_directory('ros2_arm_description')
    pkg_gz = get_package_share_directory('ros2_arm_gazebo')

    xacro_file = os.path.join(pkg_desc, 'urdf', 'ros2_arm_gz.urdf.xacro')
    world_file = os.path.join(pkg_gz, 'worlds', 'arm_world.sdf')
    bridge_config = os.path.join(pkg_gz, 'config', 'ros2_arm_bridge.yaml')
    gz_sim_launch = os.path.join(
        get_package_share_directory('ros_gz_sim'), 'launch', 'gz_sim.launch.py')

    # 把 xacro 展开成 URDF，作为参数传给相关节点
    robot_description = {
        'robot_description': ParameterValue(Command(['xacro ', xacro_file]), value_type=str)
    }

    # ① 模型 → TF 树 + /robot_description 话题
    rsp = Node(package='robot_state_publisher', executable='robot_state_publisher',
               parameters=[robot_description, {'use_sim_time': True}], output='screen')

    # ② 启动 Gazebo 仿真器（-r = 立即开始运行，不要停在暂停状态）
    gazebo = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(gz_sim_launch),
        launch_arguments={
            'gz_args': ['-r -v4 ', LaunchConfiguration('world')],
            'on_exit_shutdown': 'true',
        }.items(),
    )

    # ③ ROS ↔ Gazebo 话题桥（本项目桥接 clock）
    bridge = Node(package='ros_gz_bridge', executable='parameter_bridge',
                  arguments=['--ros-args', '-p', f'config_file:={bridge_config}'],
                  output='screen')

    # ④ 把机器人"生成"到世界里（从 /robot_description 话题读取模型）
    spawn = Node(package='ros_gz_sim', executable='create',
                 arguments=['-topic', 'robot_description',
                            '-name', 'ros2_arm',
                            '-x', '0.0', '-y', '0.0', '-z', '0.0'],
                 output='screen')

    # ⑤⑥⑦ 依次激活三个控制器（延迟 5 秒，等 Gazebo 把 ros2_control 插件加载完）
    def spawner(name):
        return Node(package='controller_manager', executable='spawner',
                    arguments=[name, '--controller-manager', '/controller_manager'],
                    output='screen')

    load_controllers = TimerAction(period=5.0, actions=[
        spawner('joint_state_broadcaster'),
        spawner('ros2_arm_controller'),
        spawner('finger_controller'),
    ])

    return LaunchDescription([
        DeclareLaunchArgument('world', default_value=world_file,
                              description='世界文件路径'),
        rsp,
        gazebo,
        bridge,
        spawn,
        load_controllers,
    ])
```

### 7.5.1 逐段讲解（这张表是本章的重点）

| 步骤 | 干了什么 | 为什么这么做 | 出错时的典型症状 |
|------|---------|-------------|----------------|
| ① robot_state_publisher | 读 URDF，算出每个连杆的坐标系，发布 `/tf` 和 `/robot_description` | RViz 和 Gazebo 都要靠它 | RViz 里模型"零件散开" |
| ② Gazebo | 加载世界文件并开始跑 | `-r` 表示 run，**不加就停在暂停状态** | 机械臂悬空不动、时钟不走 |
| ③ 话题桥 | 翻译 `/clock` | 没有它，所有节点收不到仿真时间 | `use_sim_time` 相关超时、TF 报"时间倒退" |
| ④ create | 把模型实例化到世界里 | 从话题读模型，避免重复写路径 | Gazebo 里空无一人 |
| ⑤⑥⑦ spawner | 依次激活 3 个控制器 | 控制器要等 `controller_manager` 存在（它由 Gazebo 插件创建） | `Could not contact service...` 反复刷 |

**关于 `TimerAction(period=5.0)`**：`spawner` 本身会**自动重试等待** `controller_manager`，所以不加定时器也能成功——只是启动日志里会先出现几行 `Could not contact service /controller_manager/list_controllers` 的黄色告警，**那不是错误**。加 5 秒延迟只是让日志干净、心智负担小。**如果你看到那行告警，请放心，它会自己重试成功。**

**`on_exit_shutdown: true`**：关掉 Gazebo 窗口时，顺便把整个 launch（含其他节点）都关掉，省得留下"僵尸进程"。

### 7.5.2 启动与验收（阶段 2 的过关标准）

```bash
cd ~/ros2_arm
colcon build --symlink-install
source install/setup.bash
ros2 launch ros2_arm_gazebo gz_launch.py
```

**验收清单**：

| 检查项 | 命令 / 观察点 | 期望 |
|-------|--------------|------|
| 1. Gazebo 窗口打开且机械臂站着 | 看窗口 | 橘色机械臂立在地面上，方块在旁边 |
| 2. 仿真时间在走 | `ros2 topic echo /clock --once` 连敲两次 | 秒数在增加（不是一直停在同一值） |
| 3. 三个控制器 active | `ros2 control list_controllers` | 三行，末列都是 `active` |
| 4. 接口被占用 | `ros2 control list_hardware_interfaces` | 4 个 command interface 都是 `[claimed]` |
| 5. 关节状态在广播 | `ros2 topic echo /joint_states --once` | 有 4 个关节的名字和数值 |
| 6. 能动 | 按第 06 章 6.5.3 发一条 action 轨迹 | Goal `SUCCEEDED`，窗口里机械臂真的转过去 |

**六项全过 = 阶段 2 和阶段 3 同时完成。** 到这里你已经跨过了 ROS 2 机械臂项目最难的一道坎。

## 7.6 常见问题速查

| 现象 | 原因 | 解决 |
|------|------|------|
| Gazebo 窗口打开了，但**机械臂悬空不动、时钟不走** | 仿真处于**暂停**状态 | 点左下角 ▶ 播放按钮；或确认 launch 参数里有 `-r` |
| 机械臂**掉到地下** / 一直往下掉 | 少了 `world` 链接与固定关节（见第 05 章 5.2.4） | 在 core.xacro 里补上 |
| 窗口里**一片漆黑** | 世界文件缺 `<light>` | 补光照（见 7.3） |
| Gazebo **窗口没出现**，但日志说启动了 | 图形环境问题（远程/无显示器） | 加 `-s` 只跑服务端：`gz_args: ['-r -s -v4 ', world]`，用命令行验收 |
| `ros2 launch` 报 `package 'ros2_arm_gazebo' not found` | 忘 `colcon build` 或忘 `source install/setup.bash` | 两条都做一遍 |
| 报 `searching: ['/opt/ros/humble']` 且没含你的工作空间 | 环境没加载（`source` 失败或被脚本包了一层） | 手动 `source ~/ros2_arm/install/setup.bash` 后重试；被脚本包时注意 `set -u` 会让 setup.bash 中断 |
| spawner 报 `Could not contact service` 然后自己好了 | 正常重试过程 | 忽略 |
| 控制器明明存在，spawner 却报 `Failed loading controller xxx` | **同时跑着两个仿真**：两个 Gazebo 里的插件都注册了同名节点 `/controller_manager`，spawner 连到了另一个仿真的管理器上 | `ps -ef \| grep "ign gazebo"` 确认只有一个；关掉多余的仿真后重启。**同一时刻只跑一个仿真** |
| 关闭终端后 Gazebo 还活着 | 进程没被回收 | `pkill -f 'ign gazebo'`；`pkill -f 'ros2 launc[h]'` |

> **排查心法（第 10 章会再强调一次）**：按"层"排查——**仿真层**（`/clock` 在走吗、窗口里有模型吗）→ **控制层**（`list_controllers` 是 active 吗）→ **规划层**（move_group 起了吗）。**从下往上查，别从上往下猜。**

## 7.7 动手实践提示

1. 抄写三个文件（world、bridge、launch），然后启动仿真，逐项过一遍 7.5.2 的验收清单。
2. **体验暂停的影响**：把 launch 里的 `-r -v4` 改成 `-v4`（去掉 `-r`），重新启动。你会看到 Gazebo 打开了但一切静止——**点播放按钮后恢复正常**。这就是"为什么必须加 -r"的直观答案。记得改回来。
3. **改世界，看变化**（每次只改一处）：
   - 把 `target_cube` 的 `pose` 从 `0.32 0 0.03` 改成 `0.10 0 0.03`，观察方块位置变化；
   - 在 `<world>` 里复制一份 `target_cube`（改名为 `target_cube2`，pose 改成 `0.3 0.2 0.03`），世界就多了一个方块；
   - 把 `<sun>` 的 `diffuse` 改成 `0.3 0.3 0.3 1`，看世界变暗。
4. 启动后另开终端，观察桥接是否工作：
   ```bash
   source ~/ros2_arm/install/setup.bash
   ros2 topic list | grep clock      # 有 /clock 就说明桥通了
   ros2 topic echo /clock --once
   ```
5. 在 `practice/notes.md` 回答：为什么关节状态不需要经过话题桥？`-r` 参数不加会怎样？关掉 Gazebo 窗口后为什么会连带关掉其他节点？

## 10.3 重点内容（二）：你的两个节点（完整代码）

### 10.3.1 订阅型：`practice/joint_watcher.py`

功能：持续监听 `/joint_states`，打印关节角度；当某个关节超出阈值时给出警告。**这是理解"话题订阅"的最小完整例子。**

```python
"""订阅 /joint_states，打印关节角度，并在超限时告警。"""
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState


class JointWatcher(Node):
    # 告警阈值：{关节名: (下限, 上限)}
    LIMITS = {
        'base_joint': (-2.5, 2.5),
        'shoulder_joint': (-1.4, 1.4),
    }

    def __init__(self):
        super().__init__('joint_watcher')
        self.sub = self.create_subscription(
            JointState, '/joint_states', self.on_joint_state, 10)
        self.count = 0
        self.get_logger().info('joint_watcher 启动，等待 /joint_states ...')

    def on_joint_state(self, msg: JointState):
        self.count += 1
        if self.count % 50 != 0:          # 每 50 条打印一次，避免刷屏
            return
        pairs = dict(zip(msg.name, msg.position))
        text = ', '.join(f'{n}={p:+.3f}' for n, p in pairs.items())
        self.get_logger().info(text)

        for name, (lo, hi) in self.LIMITS.items():
            if name in pairs and not (lo <= pairs[name] <= hi):
                self.get_logger().warn(
                    f'警告：{name} 当前 {pairs[name]:+.3f} 超出安全范围 [{lo}, {hi}]')


def main():
    rclpy.init()
    node = JointWatcher()
    try:
        rclpy.spin(node)                  # 一直转，直到 Ctrl+C
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

**运行方式（注意用系统 Python）**：

```bash
source /opt/ros/humble/setup.bash
source ~/ros2_arm/install/setup.bash
/usr/bin/python3 ~/ros2_arm/practice/joint_watcher.py
```

> ⚠️ **必须用 `/usr/bin/python3`**：rclpy 装在 ROS Humble 的 Python 3.10 环境里，而 WorkBuddy 自带的 Python 3.13 里没有它（这就是第 02 章那个坑的另一面）。直接敲 `python3` 时如果 PATH 被污染就会报 `No module named 'rclpy'`。

### 10.3.2 控制型：`practice/sine_sweep.py`

功能：通过 **action** 给 `ros2_arm_controller` 发一条"三个关节按正弦规律摆动"的轨迹。**这是理解 action、轨迹结构、QoS 的最快路径。**

```python
"""让机械臂按正弦规律摆动：演示如何使用 action 发送关节轨迹。"""
import math

import rclpy
from builtin_interfaces.msg import Duration
from control_msgs.action import FollowJointTrajectory
from rclpy.action import ActionClient
from rclpy.node import Node
from trajectory_msgs.msg import JointTrajectory, JointTrajectoryPoint


class SineSweep(Node):
    JOINT_NAMES = ['base_joint', 'shoulder_joint', 'elbow_joint']

    def __init__(self):
        super().__init__('sine_sweep')
        self.client = ActionClient(
            self, FollowJointTrajectory,
            '/ros2_arm_controller/follow_joint_trajectory')

    def build_trajectory(self, cycles=2, steps=80, period=6.0) -> JointTrajectory:
        traj = JointTrajectory()
        traj.joint_names = self.JOINT_NAMES
        for i in range(steps + 1):
            phase = 2.0 * math.pi * cycles * i / steps
            point = JointTrajectoryPoint()
            point.positions = [
                0.6 * math.sin(phase),                        # 底座：左右摆
                -0.4 + 0.4 * math.sin(2.0 * phase),            # 肩：抬落
                0.5 * math.cos(phase),                        # 肘：伸屈
            ]
            point.velocities = [0.0, 0.0, 0.0]
            t = period * i / steps
            point.time_from_start = Duration(
                sec=int(t), nanosec=int((t - int(t)) * 1e9))
            traj.points.append(point)
        return traj

    def run(self, timeout=10.0):
        self.get_logger().info('等待控制器 action 服务器 ...')
        if not self.client.wait_for_server(timeout_sec=timeout):
            self.get_logger().error(
                '找不到控制器。请确认已启动 ros2_arm_gazebo gz_launch.py')
            return

        goal = FollowJointTrajectory.Goal()
        goal.trajectory = self.build_trajectory()

        self.get_logger().info('发送正弦轨迹 ...')
        send_future = self.client.send_goal_async(goal)
        rclpy.spin_until_future_complete(self, send_future)
        goal_handle = send_future.result()
        if goal_handle is None or not goal_handle.accepted:
            self.get_logger().error('目标被控制器拒绝')
            return

        result_future = goal_handle.get_result_async()
        rclpy.spin_until_future_complete(self, result_future)
        status = result_future.result().status
        self.get_logger().info(f'执行结束，状态码 = {status}（4 = 成功）')


def main():
    rclpy.init()
    node = SineSweep()
    try:
        node.run()
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

**运行**：

```bash
source ~/ros2_arm/install/setup.bash
/usr/bin/python3 ~/ros2_arm/practice/sine_sweep.py
```

**你要重点体会三件事**：
1. **`wait_for_server` 是必须的**：控制器可能还没起来，不等就会发失败；
2. **轨迹 = 关节名 + 一串带时间戳的点**：`time_from_start` 是相对于轨迹起点的时刻，不是绝对时间；
3. **状态码 4 = SUCCEEDED**：学会看状态码，而不是"看起来动了就算成功"。

## 10.4 重点内容（三）：五步排错法

### 第一步：看日志的最后一行

ROS 2 的报错通常把**真正的因**写在最后一段（前面都是调用栈）。先读最后 3 行，再往上找。

```bash
# launch 的日志在终端；colcon 的日志在文件里：
cat ~/ros2_arm/log/latest_build/<包名>/stdout_stderr.log | tail -30
```

### 第二步：判断"是哪一层"出问题

| 现象 | 先查哪一层 | 命令 |
|------|-----------|------|
| 机械臂没出现 / 悬空不动 | 仿真层 | 看窗口、`ros2 topic echo /clock --once` |
| 机械臂出现但不动 | 控制层 | `ros2 control list_controllers`、`list_hardware_interfaces` |
| 控制器起不来 | 控制层 + 参数 | 核对关节名三处一致（06 章 6.4.2） |
| Plan 失败 | 规划层 | RViz 报错、`kinematics.yaml` |
| Plan 成功但不动 | 接口层 | `ros2 action list`、`moveit_controllers.yaml` 的控制器名 |

### 第三步：确认"名字"与"路径"（最高频的根因）

按顺序核对：
1. 关节名：URDF ↔ ros2_control.xacro ↔ controllers.yaml ↔ moveit_controllers.yaml；
2. 控制器名：controllers.yaml ↔ moveit_controllers.yaml；
3. 文件名与路径：CMakeLists 里 install 的目录 ↔ 实际存在的目录 ↔ launch 里拼的路径。

```bash
# 一条命令核对全部关节名
grep -rho "[a-z_]*_joint" ~/ros2_arm/src/ros2_arm_description/urdf/*.xacro \
  ~/ros2_arm/src/ros2_arm_bringup/config/*.yaml | sort -u
```

### 第四步：确认环境加载对了

```bash
echo $ROS_DISTRO                 # humble
ros2 pkg list | grep ros2_arm    # 你的包在里面吗
```
如果没有 —— 你没 `source ~/ros2_arm/install/setup.bash`，或者 `colcon build` 没成功。
**注意症状**：报错里出现 `searching: ['/opt/ros/humble']`（只有系统路径、没有你的工作空间）时，**这是环境问题，不要重新编译、不要怀疑代码**。

### 第五步：回到"最小可验证单元"

大问题拆小：
- 不启动 Gazebo，先只验证 RViz 里模型对不对（第 05 章）；
- 不启动 MoveIt，先验证控制器能不能执行 action（第 06 章 6.5.3）；
- 不写新节点，先用 `ros2 action send_goal` 手动发一次。

**每一步都能单独验证，问题就一定能在某一步暴露。**

### 三条纪律

1. **一次只改一处**，改完立刻验证；
2. **改坏就改回去**（所以要有 git 或手动备份）；
3. **不要靠重装系统解决问题**——ROS 2 的报错几乎总能定位到具体文件。

## 10.6 动手实践提示

1. 把 10.3 的两个脚本抄进 `practice/`，先跑 `joint_watcher.py`（只需仿真在跑），再跑 `sine_sweep.py`（需要控制器 active）。**看到机械臂按你写的代码摆动，是本项目最有成就感的时刻。**
2. **改参数玩**：把 `sine_sweep.py` 里的 `cycles` 改成 0.5（半圈慢摆）、`period` 改成 3.0（更快），或把肩关节那行的系数改成 0.1（几乎不动）。每次只改一处。
3. **练一次五步排错法**：故意把 `sine_sweep.py` 里的 action 名字改成 `/ros2_arm_controller/follow_joint_trajector`（少个 y），运行看现象，然后按五步法定位它（其实第一步就能看出来）。改回来。
4. 在 `practice/notes.md` 写下你**真实卡住过的问题**和解决过程（哪怕只是忘 source）。这份记录比任何教程都有价值——半年后你还会用到它。

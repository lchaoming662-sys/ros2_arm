# 第 09 章 功能模块划分

> 前 8 章是"按文件学"，本章是"按功能看"。学会用模块视角看项目，你才能**独立做下一个项目**。

---

## 9.1 学习目标

读完本章你应该能够：
1. 把项目拆成 5 个功能模块，并说清每个模块的输入输出；
2. 画出模块之间的接口（话题 / action / 参数）；
3. 说出每个模块**验收标准**和**最容易坏在哪**；
4. 知道往哪个模块加"相机视觉""抓取逻辑""真机"这三个扩展。

---

## 9.2 重点内容（一）：五个功能模块

| # | 模块 | 输入 | 输出 | 关键文件 | 验收标准 |
|---|------|------|------|---------|---------|
| 1 | **模型描述** | 你设计的尺寸/质量/关节参数 | URDF 模型（连杆树） | `ros2_arm_description/urdf/*.xacro` | RViz 里 Add→RobotModel 能看到机械臂，滑块能摆关节 |
| 2 | **仿真环境** | URDF + 世界文件 | 一个跑起来的虚拟世界 + `/clock` | `ros2_arm_gazebo/worlds/*.sdf`、`config/*.yaml`、`launch/gz_launch.py` | Gazebo 里机械臂稳稳立着，`/clock` 在走 |
| 3 | **控制系统** | 关节轨迹 / 夹爪目标 | 关节实际角度（`/joint_states`） | `ros2_arm_bringup/config/ros2_arm_controllers.yaml`、`ros2_arm.ros2_control.xacro` | 3 个控制器 active，接口全 `[claimed]`，发轨迹能动 |
| 4 | **运动规划** | 目标位姿 | 关节轨迹 | `ros2_arm_moveit_config/`（向导生成） | RViz 里 Plan & Execute 成功，Gazebo 里动起来 |
| 5 | **应用逻辑**（你自己扩展的） | 业务需求 | 具体动作 | `practice/` 或你新建的包 | 见第 10 章阶段 4、5 |

### 9.2.1 模块之间的依赖关系（谁依赖谁）

```
        ┌─────────────────────┐
        │ 1. 模型描述（基础）     │  所有模块都依赖它
        └──────────┬──────────┘
                   │ URDF
     ┌─────────────┼──────────────┐
     ▼             ▼              ▼
┌─────────┐  ┌──────────┐  ┌──────────────┐
│2.仿真环境 │  │3.控制系统 │  │4.运动规划      │
└─────────┘  └────┬─────┘  └──────┬───────┘
                  │  轨迹/状态      │ 轨迹
                  └───────◄────────┘
                          │
                  ┌───────▼────────┐
                  │5. 应用逻辑（可选）│
                  └────────────────┘
```

**记住这条铁律**：**模型是所有东西的地基**。第 05 章的名字拼错一个字母，第 06/07/08 章全会以不同方式失败。这就是为什么文档顺序不能跳。

### 9.2.2 模块间的"接口"（数据怎么流动）

| 接口 | 形式 | 生产者 → 消费者 | 所属模块 |
|------|------|----------------|---------|
| `/robot_description` | 话题（`std_msgs/String`） | robot_state_publisher → Gazebo create | 1 → 2 |
| `/clock` | 话题（`rosgraph_msgs/Clock`） | Gazebo（经桥） → 所有节点 | 2 → 全体 |
| `/tf`、`/tf_static` | 话题（`tf2_msgs/TFMessage`） | robot_state_publisher → RViz、MoveIt | 1 → 4 |
| `/joint_states` | 话题（`sensor_msgs/JointState`） | joint_state_broadcaster → RViz、MoveIt | 3 → 4 |
| `/ros2_arm_controller/follow_joint_trajectory` | **action** | MoveIt → ros2_arm_controller | 4 → 3 |
| `/finger_controller/gripper_cmd` | **action** | MoveIt/你 → finger_controller | 4 → 3 |
| `/controller_manager/...` | **服务** | spawner → controller_manager | 3 内部 |
| `ros2_arm_controllers.yaml` | **参数文件** | controller_manager 读取 | 3 内部 |

**看懂这张表的价值**：任何"不动"的问题，都能沿这张表往回追——比如"Execute 没反应"，就是 `action` 这一环断了，去查控制器名和 active 状态。

### 9.2.3 每个模块"最容易坏在哪"

| 模块 | 高频故障 | 排查入口 |
|------|---------|---------|
| 1 模型 | 名字拼错、漏 `inertial`、origin 写错 | `xacro 文件 > /tmp/x.xml`、`check_urdf`、RViz |
| 2 仿真 | 忘了 `-r`（暂停）、漏 light（黑屏）、缺插件（命令无响应） | Gazebo 窗口、`ros2 topic echo /clock` |
| 3 控制 | 名字三处不一致、Gazebo 未起就去加载控制器、接口未 claimed | `ros2 control list_controllers` / `list_hardware_interfaces` |
| 4 规划 | IK 不可达、控制器名不匹配、忘开 sim time | move_group 日志、`ros2 action list`、RViz Execute 报错 |
| 5 应用 | 时钟没统一、QoS 不匹配丢消息、异常没处理 | 自己的日志 + `ros2 topic info -v` 看 QoS |

## 9.3 重点内容（二）：三个扩展方向（做完主线再来）

### 扩展 A：加相机与视觉（对应原型的 akabot_aruco）

新增一个模块 6：**视觉感知**。步骤：
1. 在 `ros2_arm_core.xacro` 里给 `link3` 挂一个相机连杆（参考原型 `akabot_description/urdf/depth_camera.xacro`）；
2. 在 `arm_world.sdf` 或模型里加相机传感器插件（`ignition-gazebo-sensors-system`）；
3. 在 `ros2_arm_bridge.yaml` 里追加一条图像话题的桥接（参考原型 `akabot_bridge.yaml` 里 `camera/camera_info`）；
4. 写一个节点订阅图像 → 检测标记/颜色 → 发布物体位姿话题；
5. 让 MoveIt 的目标位姿来自这个节点，而不是你的鼠标。

### 扩展 B：抓取流程（状态机）

把"看到物体 → 移动到上方 → 下降 → 闭合夹爪 → 抬起"串成一个状态机节点。要点：
- 用 action 调用 MoveIt（`/move_action`）而不是直接发轨迹，这样能拿到"是否成功"的结果；
- 用 `/finger_controller/gripper_cmd` 控制夹爪；
- 每一步都要处理失败（规划不到就换一个接近方向）。

### 扩展 C：真机（对应原型的 akabot_bringup）

1. 实现一个继承 `SystemInterface` 的硬件组件（见第 06 章 6.6 的表）；
2. 把 URDF 里 `plugin_name` 换成你的组件；
3. 写一个真机 launch（不启动 Gazebo，只启动 `ros2_control_node` + 控制器）；
4. **上层全部复用**——这正是本架构的意义。

## 9.4 动手实践提示

1. 在 `practice/notes.md` 里，用你自己的话重画 9.2.1 的依赖图（不许照抄，凭记忆画），画完对照检查。
2. 填一张"我的项目体检表"（每列一个模块，行写：文件在哪、怎么验收、坏了查什么）。**这张表做完，你就具备了接手任意 ROS 2 机械臂项目的能力。**
3. 挑一个扩展方向，只做"可行性确认"：读原型里对应的文件（不用改），写下"如果我要做，第一步改哪个文件"。这一步能让你判断自己是否真的理解了模块边界。
4. 在 `practice/notes.md` 回答：如果我要给机械臂加一个"第六个关节"，需要改哪几个文件？（提示：至少 5 处）

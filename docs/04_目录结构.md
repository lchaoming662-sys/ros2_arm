# 第 04 章 目录结构

> 本章之后，你的 4 个包就能"编译过去"（虽然没有实际功能）。**这是从"看文档"进入"写代码"的第一步，很关键。**

---

## 4.1 学习目标

读完并做完本章你应该能够：
1. 解释工作空间、包、`src/`、`install/` 的关系；
2. 独立写出一份正确的 `package.xml` 和 `CMakeLists.txt`；
3. 顺利跑通第一次 `colcon build`，并用 `ros2 pkg list` 看到自己的包；
4. 避开"install 目录不存在导致编译失败"这个经典坑。

---

## 4.2 重点内容

### 4.2.1 三个必须分清的层级

| 层级 | 是什么 | 你的项目里 |
|------|--------|-----------|
| **工作空间 Workspace** | 一个目录，里面装着若干个包，统一编译 | `/home/lichaoming/ros2_arm` |
| **包 Package** | 一个功能单元，**必须**有 `package.xml` | `ros2_arm_description` |
| **源代码/资源文件** | 包内的具体文件（xacro、yaml、py、world…） | `urdf/ros2_arm_core.xacro` |

**两个硬性约定**（违反了 colcon 就找不到你的包）：
1. **所有包的目录必须放在 `<工作空间>/src/` 下面**（可以再嵌套一层，`src/foo/bar_pkg` 也合法）；
2. **包的目录里必须有 `package.xml`**，且其中的 `<name>` 与目录名一致（建议一致，避免混乱）。

### 4.2.2 你的完整目录树（含"哪个文件在哪一章写"）


**观察一个设计原则**：`description` 只管"长什么样"，`bringup` 只管"参数与硬件"，`gazebo` 只管"仿真环境"，`moveit_config` 只管"规划"。**一个包只做一件事**——这是 ROS 2 的社区惯例，也是你以后能快速找到文件的原因。

### 4.2.3 `package.xml` 怎么写（4 个包的完整代码）

`package.xml` 是包的"身份证 + 依赖清单"。类比 Python 的 `requirements.txt`。

**① `src/ros2_arm_description/package.xml`**

```xml
<?xml version="1.0"?>
<?xml-model href="http://download.ros.org/schema/package_format3.xsd" schematypens="http://www.w3.org/2001/XMLSchema"?>
<package format="3">
  <name>ros2_arm_description</name>
  <version>0.1.0</version>
  <description>ros2_arm 的模型描述文件（URDF / Xacro）</description>
  <maintainer email="you@example.com">your_name</maintainer>
  <license>MIT</license>

  <!-- 编译工具：C++ 包一律依赖 ament_cmake；纯 Python 包用 ament_python -->
  <buildtool_depend>ament_cmake</buildtool_depend>

  <!-- 运行时需要的包：显示模型要它们 -->
  <exec_depend>joint_state_publisher</exec_depend>
  <exec_depend>joint_state_publisher_gui</exec_depend>
  <exec_depend>robot_state_publisher</exec_depend>
  <exec_depend>xacro</exec_depend>
  <exec_depend>rviz2</exec_depend>

  <export>
    <build_type>ament_cmake</build_type>
  </export>
</package>
```

**② `src/ros2_arm_bringup/package.xml`**

```xml
<?xml version="1.0"?>
<?xml-model href="http://download.ros.org/schema/package_format3.xsd" schematypens="http://www.w3.org/2001/XMLSchema"?>
```

**③ `src/ros2_arm_gazebo/package.xml`**

```xml
<?xml version="1.0"?>
```

**④ `ros2_arm_moveit_config` 的 `package.xml` 不用你写**——第 08 章的配置向导会自动生成一份内容很长的版本。

### 4.2.4 `CMakeLists.txt` 怎么写（3 个包的完整代码）

`CMakeLists.txt` 告诉编译器"怎么装我的文件"。对纯资源包（只有 xacro/yaml/launch）来说，它短得只有三行有效内容。

**① `ros2_arm_description/CMakeLists.txt`**

```cmake
cmake_minimum_required(VERSION 3.8)
project(ros2_arm_description)

find_package(ament_cmake REQUIRED)

# 把资源目录安装到 install/<包名>/share/<包名>/ 下
install(
  DIRECTORY config launch rviz urdf
  DESTINATION share/${PROJECT_NAME}
)

ament_package()
```

**② `ros2_arm_bringup/CMakeLists.txt`**

```cmake
cmake_minimum_required(VERSION 3.8)
project(ros2_arm_bringup)

find_package(ament_cmake REQUIRED)

install(
  DIRECTORY config launch
  DESTINATION share/${PROJECT_NAME}
)

ament_package()
```

**③ `ros2_arm_gazebo/CMakeLists.txt`**

```cmake
cmake_minimum_required(VERSION 3.8)
project(ros2_arm_gazebo)

find_package(ament_cmake REQUIRED)

install(
  DIRECTORY config launch worlds
  DESTINATION share/${PROJECT_NAME}
)

ament_package()
```

### 4.2.5 一个真实踩过的坑：`install(DIRECTORY ...)` 的目录必须存在

原型 akabot 项目里，`akabot_bringup` 的 CMakeLists 写了 `install(DIRECTORY config launch ...)`，但仓库里**没有 `launch` 目录**（漏提交），结果：

```
CMake Error at ament_cmake_symlink_install/ament_cmake_symlink_install.cmake:105 (message):
  ament_cmake_symlink_install_directory() can't find
  '/home/lichaoming/akabot-main/akabot_bringup/launch'
```

**症状**：编译在你以为"啥也没干"的地方失败，报错里出现一个你从没提过的路径。

**原因**：`install(DIRECTORY a b c ...)` 会逐个检查每个目录是否存在，缺一个就整体失败。

**两条对策**：
1. 补上目录（哪怕里面暂时空着，放一个 `.gitkeep` 占位）；
2. 或者只 install 你确实有的目录（本项目已经为你建好了 `launch/`、`worlds/` 等所有目录，**理论上不会踩到**——但你要知道这个错长什么样）。

**引申经验**：CMakeLists 里写的目录、package.xml 里写的依赖、YAML 里写的文件路径，三者**任何一个对不上都会失败**，且报错位置往往不在真正的原因处。遇到莫名其妙的报错，先回去核对"名字拼写和路径是否存在"。

### 4.2.6 命名约定（本项目统一遵守）

| 对象 | 约定 | 示例 |
|------|------|------|
| 包名 | 全小写 + 下划线 | `ros2_arm_description` |
| 文件（Python/launch） | 小写下划线 + `.py` | `gz_launch.py`、`display.launch.py` |
| 文件（xacro/urdf） | 小写下划线，`urdf` 结尾的才是"总装" | `ros2_arm_core.xacro`、`ros2_arm_gz.urdf.xacro` |
| 关节名 | 小写下划线 + `_joint` 结尾 | `shoulder_joint` |
| 连杆名 | 小写下划线 + `_link` 或语义名 | `base_link`、`link2`、`gripper_base` |
| 控制器名 | 功能 + `_controller` | `ros2_arm_controller`、`finger_controller` |

### 4.2.7 第一次编译

```bash
cd ~/ros2_arm
colcon build --symlink-install
source install/setup.bash
ros2 pkg list | grep ros2_arm
```

**期望看到 4 个包名**（`ros2_arm_moveit_config` 此时还不存在，所以是 3 个）：

```
ros2_arm_bringup
ros2_arm_description
ros2_arm_gazebo
```

如果 package.xml 或 CMakeLists 写错，报错会写进 `log/latest_build/<包名>/stdout_stderr.log`，**去看那个文件，不要只看终端最后几行**。

**一个诊断技巧**：判断"是不是真的编译成功了"，不要看有没有 `install/` 目录（失败时它也会被创建），要比对包的数量：

```bash
ls src | wc -l      # 源码里有几个包目录
ls install | grep -vcE '^(setup\.|local_setup|_local_setup|COLCON_IGNORE|\.)'   # install 里有几个
```

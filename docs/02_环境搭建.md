## 2.1 学习目标

读完并做完本章你应该能够：
1. 说明 ROS 2、Gazebo、MoveIt 三者的安装方式与依赖关系；

## 2.2 重点内容

### 2.2.1 系统要求

| 项目 | 要求 | 你的机器（已核对） |
|------|------|------------------|
| 操作系统 | Ubuntu 22.04 LTS（Jammy） | ✅ Ubuntu 22.04.5 LTS |
| ROS 2 版本 | **Humble**（与 22.04 严格绑定，不要装 Jazzy） | ✅ `/opt/ros/humble` 存在 |
| 仿真器 | **Gazebo Fortress**（内部名 Ignition Gazebo 6） | ✅ `ign gazebo --version` → 6.18.0 |
| 运动规划 | MoveIt 2（Humble 版） | ✅ 已安装 |
| 图形界面 | X11 或 Wayland 桌面（要显示 RViz 和 Gazebo 窗口） | ✅ `DISPLAY=:0` |
| 磁盘 | 建议 ≥ 20 GB 可用 | 自行确认 `df -h /` |
| Docker | **不需要**（原型仓库里的 Dockerfile 是给 Nvidia Jetson Nano 准备的） | — |

**为什么必须 Humble + Fortress 这一对**：ROS 2 的发行版与 Ubuntu 版本强绑定（Humble↔22.04），而 Humble 官方支持的仿真器就是 Fortress。装成别的组合会出现"桥接库版本不匹配"这类极难排查的问题。

### 2.2.2 三步安装（若你已装好可只做验证）

**第 1 步：ROS 2 Humble 基础**

```bash
sudo apt update && sudo apt install -y \
  ros-humble-desktop \
  python3-colcon-common-extensions \
  python3-rosdep
```

> `ros-humble-desktop` 包含 RViz、示例程序等常用组件。国内网络慢的话，可以给 apt 换国内镜像（华为云/清华源）再装。

**第 2 步：仿真（Gazebo Fortress + 与 ROS 的桥）**

```bash
sudo apt install -y \
  ros-humble-ros-gz \
  ros-humble-ros-gz-bridge \
  ros-humble-ros-gz-sim \
  ros-humble-ros-gz-image \
  ros-humble-ros-ign-gazebo
```

- `ros-gz-*`：ROS 2 与 Gazebo 的桥接与启动工具（`gz_sim.launch.py`、`ros_gz_sim create` 都在这里）；
- `ros-ign-gazebo`：**过渡兼容包**。虽然名字里是老的 "ign"，但它提供了一批老式路径（比如 `ign_gazebo.launch.py`），很多教程和老项目还在用。**本机实测必须装它**，否则原型 akabot 启动时会报 `package 'ros_ign_gazebo' not found`。

**第 3 步：控制与规划**

```bash
sudo apt install -y \
  ros-humble-ign-ros2-control \
  ros-humble-gz-ros2-control \
  ros-humble-controller-manager \
  ros-humble-joint-trajectory-controller \
  ros-humble-gripper-controllers \
  ros-humble-xacro \
  ros-humble-robot-state-publisher \
  ros-humble-joint-state-publisher \
  ros-humble-joint-state-publisher-gui \
  ros-humble-moveit \
  ros-humble-moveit-configs-utils \
  ros-humble-moveit-setup-assistant \
  ros-humble-rviz2
```

**关键理解**：`ros-humble-ign-ros2-control` 和 `ros-humble-gz-ros2-control` 是同一个东西的两个名字（上游把 ign_ 前缀改名成 gz_ 时留了过渡包），它们把 Gazebo 和 ros2_control 接在一起——**没有它，仿真里的机械臂就是一坨不会动的几何体**。

### 2.2.3 依赖自查表（用这条命令一次核对）

```bash
for p in ros-humble-desktop ros-humble-ros-gz ros-humble-ros-gz-bridge ros-humble-ros-gz-sim \
         ros-humble-ros-ign-gazebo ros-humble-gz-ros2-control ros-humble-controller-manager \
         ros-humble-joint-trajectory-controller ros-humble-gripper-controllers ros-humble-xacro \
         ros-humble-robot-state-publisher ros-humble-joint-state-publisher ros-humble-joint-state-publisher-gui \
         ros-humble-moveit ros-humble-moveit-configs-utils ros-humble-moveit-setup-assistant ros-humble-rviz2; do
  dpkg -s $p >/dev/null 2>&1 && echo "OK   $p" || echo "缺失 $p"
done
```

逐个补齐缺失项即可。**注意**：换行要用 `\` 连接，整段是一行命令。

### 2.2.4 创建你的工作空间

```bash
mkdir -p ~/ros2_arm/src
cd ~/ros2_arm
colcon build --symlink-install
source install/setup.bash
```

三条命令的含义：

| 命令 | 作用 |
|------|------|
| `mkdir -p ~/ros2_arm/src` | 建立工作空间。**ROS 2 强制约定**：源码必须放在 `src/` 子目录里，colcon 只在 `src/` 里找包 |
| `colcon build --symlink-install` | 编译 `src/` 下所有包。`--symlink-install` 表示"安装时用软链接而不是复制"，好处是**改了 Python 脚本和 YAML 不用重新编译**，对新手极其友好 |
| `source install/setup.bash` | 把你刚编译的包"登记"进当前终端的环境变量。**每开一个新终端都要 source**，否则系统找不到你的包 |

编译产物说明：
- `build/`：中间文件（CMake 缓存等），可以随时删；
- `install/`：最终产物，`source` 的就是这里；
- `log/`：每次编译的日志，**报错时来这里看详情**，例如 `log/latest_build/<包名>/stdout_stderr.log`。

### 2.2.5 本机特有的两个坑（务必记住）

> 这两个坑是在帮你在跑原型项目时**实际踩到并解决**的，你的项目一定会再遇到。

#### 坑 1：WorkBuddy 的 Python 3.13 会抢占系统 Python 3.10

**症状**：

```
ModuleNotFoundError: No module named 'catkin_pkg'
CMake Error at .../ament_package_xml.cmake:95 (message)
  execute_process(/home/lichaoming/.workbuddy/binaries/python/versions/3.13.12/bin/python3 ...)
```

**原因**：AI 沙箱的 `PATH` 里排在前面的 Python 3.13 被 CMake 选中，而 ROS Humble 的工具链是给系统 Python 3.10 写的。

**解决**：用"干净 PATH"编译：

```bash
env -i HOME=$HOME PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
  bash -c "source /opt/ros/humble/setup.bash && cd ~/ros2_arm && colcon build --symlink-install"
```

**你在自己的普通终端里编译不会遇到这个问题**（系统 PATH 本来就正常），只有被脚本包一层或让 AI 代跑时才需要这个写法。

**如果已经踩了**：错误路径会被写进 `build/<包名>/CMakeCache.txt`，只重跑没用，要先删掉污染文件：

```bash
rm ~/ros2_arm/build/*/CMakeCache.txt   # 然后重新 colcon build
```

#### 坑 2：`ros_ign_gazebo` 这类"过渡包"缺一个就卡住

**症状**：`PackageNotFoundError: "package 'ros_ign_gazebo' not found"`，但 `ls /opt/ros/humble/share | grep gazebo` 明明有一堆。

**原因**：老项目/老教程引用的老式包名，需要单独装过渡包。

**解决**：装 `ros-humble-ros-ign-gazebo`（见 2.2.2 第 2 步）。**本项目自己的 launch 用的是新式 `ros_gz_sim`，不会踩这个坑**，但你会有大量机会去参考老教程。

**顺带一条**：`sudo` 需要密码时，可以让系统在你桌面上弹一个授权窗口（Agent 全程接触不到密码），例如：

```bash
pkexec /bin/bash /tmp/install_xxx.sh
```

### 2.2.6 环境健康检查（5 条命令）

```bash
# 1. ROS 2 版本与发行版
echo $ROS_DISTRO            # 期望 humble（先 source /opt/ros/humble/setup.bash）

# 2. 仿真器
ign gazebo --version         # 期望 Gazebo Sim, version 6.x

# 3. 控制与规划包
ros2 pkg list | grep -E "gz_ros2_control|moveit_ros_move_group|joint_trajectory_controller"

# 4. 图形环境（决定能不能把窗口显示出来）
echo "DISPLAY=$DISPLAY  WAYLAND=$WAYLAND_DISPLAY"

# 5. 你的工作空间
cd ~/ros2_arm && source install/setup.bash && ros2 pkg list | grep ros2_arm
```

第 5 条现在会**没有输出**——因为你的包还是空的，这很正常。做完第 04 章后再回来跑它。

## 2.3 动手实践提示

1. 跑一遍 2.2.3 的自查表，把缺失的包装上（用 `pkexec` 脚本方式或你自己的终端）。
2. 跑一遍 2.2.6 的五条命令，把输出抄进 `practice/notes.md`，作为"环境基线"。以后出问题先跟基线对比。
3. **故意制造一次错误来学习**（很重要）：在 `~/ros2_arm/src` 下随便建一个目录 `test_pkg`，里面放一个空文件 `package.xml`，然后 `colcon build`，观察报错。看完把 `test_pkg` 删掉。
   - 这一步的目的是让你**亲眼见到**"空 package.xml 会报什么错"，避免以后被吓到。
4. 记住三个"重启大法"的粒度：改 Python/YAML → 重开 launch；改 xacro/URDF → 重开 launch；改 CMakeLists/package.xml/新增文件 → **必须 `colcon build` 再重开 launch**。

## 5.2 重点内容（一）：URDF 基础

### 5.2.1 URDF 是什么

URDF（Unified Robot Description Format）是 ROS 里描述机器人的 XML 格式。它只描述**几何与运动学**，不描述外观贴图、也不描述"该怎么动"。

**URDF 用两种元素描述整个机器人：**

| 元素 | 含义 | 类比 |
|------|------|------|
| `<link>` 连杆 | 一个**刚体**零件 | 人的"大臂骨""小臂骨" |
| `<joint>` 关节 | 两个刚体之间的**连接** | 人的"肘关节" |

**一个机器人 = 一棵树**：以 `base_link` 为根，通过关节连出一片连杆树。**树里不能有环**（不能出现"link2 既连 link1 又连 link3"这种闭环），这是 URDF 的硬性限制。

### 5.2.2 每个 `<link>` 里写三样东西

```xml
<link name="link2">
  <inertial>  ... </inertial>   <!-- 质量与惯量：物理引擎用来算它怎么动 -->
  <visual>    ... </visual>     <!-- 外观：RViz 里画出来的样子 -->
  <collision> ... </collision>  <!-- 碰撞体：物理引擎用来算它撞到什么 -->
</link>
```

三者的区别非常关键：

| 标签 | 谁在用 | 可以省吗 | 省了会怎样 |
|------|--------|---------|-----------|
| `visual` | RViz、Gazebo 渲染 | 不建议 | 看不见这个零件（但机器人在，只是隐形） |
| `collision` | Gazebo 物理引擎 | 可以 | 零件能穿模（互相穿透），仿真不真实 |
| `inertial` | Gazebo 物理引擎 | **绝对不行** | 质量默认为 0 或非法值 → 机械臂**抖动、爆炸、飞天** |

**新手最省事的做法**：`visual` 和 `collision` 用**同一个几何体**（先简单化，两个都用长方体/圆柱），`inertial` 用真实的质量估算值。

### 5.2.3 每个 `<joint>` 里写四样东西

```xml
<joint name="elbow_joint" type="revolute">
  <parent link="link2"/>              <!-- 父连杆 -->
  <child  link="link3"/>              <!-- 子连杆 -->
  <origin xyz="0 0 0.25" rpy="0 0 0"/> <!-- 关节在父连杆坐标系中的位置和朝向 -->
  <axis   xyz="0 1 0"/>               <!-- 绕哪个轴转（只在关节自己的坐标系里有效） -->
  <limit lower="-2.0" upper="2.0" effort="10" velocity="1.5"/>
</joint>
```

**关节类型（type）——本项目用到 3 种：**

| type | 含义 | 本项目的例子 |
|------|------|------------|
| `fixed` | 完全固定，不能动 | `gripper_joint`（夹爪座焊死在小臂上） |
| `revolute` | 转动，**有角度限位** | `base_joint`、`shoulder_joint`、`elbow_joint` |
| `revolute` | 绕轴旋转，有角度限位 | `finger_right_joint`（夹爪开合；`finger_left_joint` 用 `<mimic>` 反向跟随） |

> 补充：`continuous` 是无限位的转动（轮子用），本项目不用。

**`<origin xyz rpy>` 新手最容易搞错**：
- `xyz` 和 `rpy` 都是**在父连杆坐标系里**表达"子连杆坐标系的原点在哪、朝向如何"；
- `rpy` 是"绕 X 轴、再绕 Y 轴、再绕 Z 轴"依次旋转的角度（单位弧度）；
- **关节的 `<axis>` 表达在关节自己的坐标系里**（也就是经过 `<origin>` 变换后），所以轴写成 `0 0 1` 表示"沿子坐标系的 Z 轴转动"。

**坐标系约定**：ROS 标准是 X 向前、Y 向左、Z 向上。机械臂通常竖直安装，所以"向上"的偏移都写在 `xyz` 的第三个分量上（比如 `0 0 0.25`）。

### 5.2.4 `world` 链接：一个必须知道的"技巧"

**问题**：URDF 只描述机器人自己，**没有"地面"这个概念**。你把模型丢进 Gazebo，如果没有东西拴住它，它会像一块砖头一样自由落体。

**原型项目的解法**（已验证可行，本项目照抄）：在 URDF 里加一个空的 `world` 连杆，然后用一个固定关节把 `base_link` 钉在 `world` 上：

```xml
<link name="world"/>
<joint name="world_base_joint" type="fixed">
  <parent link="world"/>
  <child  link="base_link"/>
</joint>
```

Gazebo 在把 URDF 转成自己的 SDF 格式时，看到 `world` 这个名字，就知道"把 base_link 焊死在物理世界的原点上"。**机械臂从此稳如泰山。**

> 这是 ROS 社区流传最广的"土办法"，但它是有效的、被广泛使用的。你以后看别人的项目，看到莫名其妙的 `<link name="world"/>`，就知道是干这个的。

## 5.3 重点内容（二）：Xacro 语法

### 5.3.1 为什么要用 Xacro

6 个关节各个写一遍 `<inertial>` 里的惯量公式，既啰嗦又容易算错。Xacro 是 URDF 的"模板语言"，提供 4 个利器：

| 语法 | 作用 | 例子 |
|------|------|------|
| `<xacro:property>` | 定义常量 | `<xacro:property name="arm_len" value="0.25"/>` |
| `${}` | 在属性里做数学运算 | `xyz="0 0 ${arm_len/2}"` |
| `<xacro:macro>` | 定义可复用的"函数" | 一个宏搞定所有长方体的惯量 |
| `<xacro:include>` | 把另一个文件包含进来 | 主装配文件 include 各个零件文件 |

**注意**：Xacro 文件**不能直接被 RViz / Gazebo 读取**，必须先用 `xacro` 命令"展开"（把宏和变量算完）成纯 URDF。launch 文件里用 `Command(['xacro ', 路径])` 就是在做这件事。

### 5.3.2 三个必会的写法

**① 变量与运算**

```xml
<xacro:property name="link2_length" value="0.25"/>
<origin xyz="0 0 ${link2_length/2}"/>   <!-- 展开后是 0 0 0.125 -->
```

**② 宏（带参数的可复用片段）**

```xml
<xacro:macro name="box_inertia" params="m x y z">
  <inertial>
    <mass value="${m}"/>
    <inertia ixx="${m*(y*y+z*z)/12}" ixy="0" ixz="0"
             iyy="${m*(x*x+z*z)/12}" iyz="0"
             izz="${m*(x*x+y*y)/12}"/>
  </inertial>
</xacro:macro>

<!-- 调用：传递 长x宽高 和 质量，自动算出惯量 -->
<link name="link2">
  <xacro:box_inertia m="0.4" x="0.03" y="0.03" z="0.25"/>
</link>
```

**③ 包含**

```xml
<xacro:include filename="$(find ros2_arm_description)/urdf/ros2_arm_core.xacro"/>
```

`$(find 包名)` 是 ROS 的路径替换语法，运行时会被换成该包的 `share` 目录绝对路径。**注意**：它靠 `colcon build` 安装后的路径生效，所以**改了 xacro 不用重新 build（软链接安装），但新增或删除文件后要重新 build**。

### 5.3.3 惯量：新手必看的 5 分钟物理

**惯量（inertia）** 描述"这个物体容不容易被转动"。物理引擎靠它算力矩和加速度。三个主轴惯量 `ixx / iyy / izz` 对应绕三个轴的转动难易程度。

**两个可以直接抄的公式**（本项目全部用这两个）：

| 形状 | 公式 |
|------|------|
| 长方体（尺寸 x×y×z，质量 m） | `ixx = m(y²+z²)/12`，`iyy = m(x²+z²)/12`，`izz = m(x²+y²)/12` |
| 圆柱（半径 r、高 h、质量 m，轴向为 z） | `ixx = iyy = m(3r²+h²)/12`，`izz = m·r²/2` |

**新手三大坑**：

1. **忘了写 `<inertial>`** → Gazebo 里机械臂会剧烈抖动甚至飞出世界。**每个非固定连杆都必须有**。
2. **质量写 0 或省略** → 同上。质量可以估，但不能是 0。
3. **惯量数量级差太多** → 抖动的另一种原因。写完后自查：一个 0.4 kg、0.25 m 长的杆，惯量应该在 `1e-3` 量级（本项目算出来是 0.0021）；如果你写成了 `2.1` 或 `1e-8`，就一定有问题。
   - **抖动应急方案**：把质量调大 10 倍、惯量按公式重算（本项目第 06 章末尾有排查表）。

## 5.4 重点内容（三）：完整代码 ── `ros2_arm_core.xacro`

> 这是项目的**核心零件库**：定义全部连杆与关节。请抄写到你项目里的
> `src/ros2_arm_description/urdf/ros2_arm_core.xacro`（现在它是空文件）。

```xml
<?xml version="1.0"?>
<!-- ============================================================
     ros2_arm_core.xacro
     作用：定义机械臂的全部连杆（link）与关节（joint）
     零位：所有关节 = 0 时，机械臂竖直向上伸直
     ============================================================ -->
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="ros2_arm">

  <!-- ================= 0. 惯量计算宏（所有连杆复用） ================= -->

  <!-- 长方体惯量：x y z 为三边长度，m 为质量 -->
  <xacro:macro name="box_inertia" params="m x y z">
    <inertial>
      <mass value="${m}"/>
      <origin xyz="0 0 0" rpy="0 0 0"/>
      <inertia ixx="${m*(y*y+z*z)/12}" ixy="0" ixz="0"
               iyy="${m*(x*x+z*z)/12}" iyz="0"
               izz="${m*(x*x+y*y)/12}"/>
    </inertial>
  </xacro:macro>

  <!-- 圆柱惯量：r 半径，h 高（轴向为 z），m 质量 -->
  <xacro:macro name="cylinder_inertia" params="m r h">
    <inertial>
      <mass value="${m}"/>
      <origin xyz="0 0 0" rpy="0 0 0"/>
      <inertia ixx="${m*(3*r*r+h*h)/12}" ixy="0" ixz="0"
               iyy="${m*(3*r*r+h*h)/12}" iyz="0"
               izz="${m*r*r/2}"/>
    </inertial>
  </xacro:macro>

  <!-- ================= 1. 颜色 ================= -->

  <xacro:property name="col_base"  value="0.55 0.55 0.58 1.0"/>
  <xacro:property name="col_arm"   value="0.90 0.45 0.10 1.0"/>
  <xacro:property name="col_joint" value="0.25 0.25 0.28 1.0"/>

  <!-- ================= 2. 尺寸与质量（要调参数只改这里） ================= -->

  <xacro:property name="base_radius"   value="0.06"/>
  <xacro:property name="base_height"   value="0.04"/>
  <xacro:property name="base_mass"     value="1.0"/>

  <xacro:property name="link1_radius"  value="0.045"/>
  <xacro:property name="link1_height"  value="0.05"/>
  <xacro:property name="link1_mass"    value="0.5"/>

  <xacro:property name="link2_width"   value="0.03"/>
  <xacro:property name="link2_length"  value="0.25"/>
  <xacro:property name="link2_mass"    value="0.4"/>

  <xacro:property name="link3_width"   value="0.025"/>
  <xacro:property name="link3_length"  value="0.22"/>
  <xacro:property name="link3_mass"    value="0.3"/>

  <xacro:property name="grip_x"        value="0.05"/>
  <xacro:property name="grip_y"        value="0.05"/>
  <xacro:property name="grip_z"        value="0.02"/>
  <xacro:property name="grip_mass"     value="0.15"/>
  <xacro:property name="finger_size"   value="0.012"/>
  <xacro:property name="finger_len"    value="0.04"/>
  <xacro:property name="finger_mass"   value="0.02"/>

  <!-- ================= 3. 世界链接 + 底座（把机械臂钉在地面上） ================= -->

  <link name="world"/>

  <joint name="world_base_joint" type="fixed">
    <parent link="world"/>
    <child  link="base_link"/>
  </joint>

  <link name="base_link">
    <xacro:cylinder_inertia m="${base_mass}" r="${base_radius}" h="${base_height}"/>
    <visual>
      <origin xyz="0 0 ${base_height/2}" rpy="0 0 0"/>
      <geometry>
        <cylinder radius="${base_radius}" length="${base_height}"/>
      </geometry>
      <material name="col_base"><color rgba="${col_base}"/></material>
    </visual>
    <collision>
      <origin xyz="0 0 ${base_height/2}" rpy="0 0 0"/>
      <geometry>
        <cylinder radius="${base_radius}" length="${base_height}"/>
      </geometry>
    </collision>
  </link>

  <!-- ================= 4. 关节 1：底座旋转（绕 Z 轴） ================= -->

  <joint name="base_joint" type="revolute">
    <parent link="base_link"/>
    <child  link="link1"/>
    <origin xyz="0 0 ${base_height}" rpy="0 0 0"/>
    <axis xyz="0 0 1"/>
    <limit lower="-3.14159" upper="3.14159" effort="10.0" velocity="1.5"/>

  <link name="link1">

      <origin xyz="0 0 ${link1_height/2}" rpy="0 0 0"/>
```

### 5.4.1 逐块讲解（对着上面的代码读）

| 代码块 | 在干什么 | 要理解的点 |
|--------|---------|-----------|
| 第 0 节 两个宏 | 把惯量公式封装成函数 | 这就是 Xacro 的价值：公式写一次，6 个连杆复用 |
| 第 1 节 颜色 | 定义 rgba 颜色常量 | RViz 里模型是灰的？说明 `material` 没写对 |
| 第 2 节 尺寸质量 | 所有数字集中在此 | **调参数只改这里**，下面的结构代码一个字不用动 |
| 第 3 节 world + base_link | 钉住底座 | 没有这段，机械臂在 Gazebo 里会往下掉 |
| 第 4~6 节 三个转动关节 | 建立"圆柱→大臂→小臂"的运动链 | 注意每个 `<origin>` 都在**父连杆**坐标系里，所以肩关节在 link1 顶部（z=link1_height） |
| 第 7 节 夹爪 | 固定关节 + 两个旋转指 | 右指主动、左指 `<mimic multiplier="-1">` 反向跟随。`<mimic>` 是"从动关节"的标准写法，**不用为它写控制器** |
| 零位姿态 | base=0, shoulder=0, elbow=0 | 竖直向上伸直；`shoulder_joint` 转起来后整条臂前倾/后仰 |

**关节链自检表**（写完对着数一遍）：

```
world ──(fixed)── base_link ──(base_joint, 转Z)── link1 ──(shoulder_joint, 转Y)── link2
      ──(elbow_joint, 转Y)── link3 ──(gripper_joint, fixed)── gripper_base
                                                              ├──(finger_right_joint, 转X)── finger_right
                                                              └──(finger_left_joint,  转X)── finger_left
```

连杆 7 个（不含 world），关节 7 个（其中 5 个可动，2 个固定）。**数不上就是漏写了。**

## 5.6 重点内容（五）：`display.launch.py`（本章就能看到成果）

把下面代码写进 `src/ros2_arm_description/launch/display.launch.py`：

```python
"""在 RViz 里显示 ros2_arm 模型，并可用滑块手动摆关节。"""
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.conditions import IfCondition, UnlessCondition
from launch.substitutions import Command, LaunchConfiguration
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    pkg_share = get_package_share_directory('ros2_arm_description')
    xacro_file = os.path.join(pkg_share, 'urdf', 'ros2_arm.urdf.xacro')
    rviz_config = os.path.join(pkg_share, 'rviz', 'display.rviz')

    use_gui = LaunchConfiguration('use_gui')

    # Command 会执行 "xacro <文件>" 并把输出（纯 URDF 文本）作为参数传给节点
    robot_description = {
        'robot_description': ParameterValue(Command(['xacro ', xacro_file]), value_type=str)
    }

    # RViz 配置文件还不存在时，就让 rviz2 用默认配置启动（避免报错吓人）
    rviz_args = ['-d', rviz_config] if os.path.exists(rviz_config) else []

    return LaunchDescription([
        DeclareLaunchArgument('use_gui', default_value='true',
                              description='true=用滑块手动摆关节，false=用默认值'),

        # 把 URDF 转成 TF 树（RViz 靠它知道零件之间的位置关系）
        Node(package='robot_state_publisher', executable='robot_state_publisher',
             output='screen', parameters=[robot_description]),

        # 滑块窗口：手动给每个关节设角度
        Node(package='joint_state_publisher_gui', executable='joint_state_publisher_gui',
             condition=IfCondition(use_gui)),

        # 无滑块时的替代：给关节发默认值
        Node(package='joint_state_publisher', executable='joint_state_publisher',
             condition=UnlessCondition(use_gui)),

        Node(package='rviz2', executable='rviz2', output='screen', arguments=rviz_args),
    ])
```

**用法与结果**：

```bash
cd ~/ros2_arm
colcon build --symlink-install
source install/setup.bash
ros2 launch ros2_arm_description display.launch.py
```

RViz 打开后**必须做一件事**（否则会看到黑屏以为模型错了）：
在左下角 **Add → RobotModel**，然后确认 "Description Topic" 是 `/robot_description`。
再拖 `joint_state_publisher_gui` 窗口里的滑块，机械臂应该跟着动。

## 5.8 常见坑速查

| 现象 | 原因 | 解决 |
|------|------|------|
| 某个关节**发指令完全不动**，位置恒为 0 | **零件几何贴合**：活动件与固定件表面刚好贴死，被接触摩擦力卡住（真实项目里最常见的一类"物理原因"故障） | 让活动件与固定件之间留 2~5 mm 间隙；行程上限也别顶到对方 |
| Gazebo 里机械臂**掉下去/乱飞** | 缺 `world` + 固定关节，或某个 link 没有 `<inertial>` | 补 `<link name="world"/>` + fixed joint；检查每个 link |
| 机械臂**剧烈抖动** | 惯量数量级错误 / 质量过小 | 用 5.3.3 的公式重算；或整体把质量放大 10 倍 |
| RViz 里**看不到模型** | 忘了 Add → RobotModel；或 URDF 展开失败 | 看终端有没有 xacro 报错；RViz 里加 RobotModel |
| RViz 里零件**位置不对/叠在一起** | `<origin>` 写错（尤其忘了 z 偏移） | 对照 5.4 代码逐个核对 origin |
| 报 `No such file or directory` | `$(find 包名)` 里的包名拼错，或没 build | 核对包名；`colcon build` 后再试 |
| 改了 xacro **没生效** | 忘 source / 忘重开 launch | `colcon build`（新增文件时）→ 重开 launch |
| Gazebo 里模型**全白没颜色** | 只写在 visual 里的 `material` 有时不被转换 | 不影响功能，可忽略；要颜色可在 `<gazebo>` 里加材质 |

## 5.8.1 实战案例：为什么夹爪"发指令但完全不动"

这是本项目在**真实试跑中踩到并解决**的坑，价值极高，请务必理解。
它同时也解释了：为什么夹爪要按**原项目的旋转方案**做，而不是"一个平移关节滑过去"。

**现象**：控制器 `finger_controller` 是 `active`，`finger_right_joint/position` 也 `[claimed]`，
但关节**一步都不动**，`GripperCommand` 目标总是 `ABORTED`（回执 `reached_goal: false`）。
三个手臂关节却完全正常——**软件全是好的**。

**第一层排查**：先怀疑"几何贴死"（活动爪底面与底板顶面共面 → 摩擦锁死）。
实测发现不是主因：给它留了 5 mm 间隙后，水平姿态下能动，**但机械臂一倾斜就又不动了**。

**真正的原因**：这是 **平移关节（prismatic）的结构性缺陷**，加上 Humble 版驱动器的限制：

1. 本机 `gz_ros2_control` 的**位置接口其实按速度控制实现**：
   `joint_velocity = position_proportional_gain × 位置误差 × update_rate`，
   而这个增益在 Humble 上**被硬编码为 0.1**——无论是写在 URDF 的 `<param>` 里，
   还是写在控制器的 YAML 里，都会被**静默忽略**（启动日志永远打印
   `The position_proportional_gain has been set to: 0.1`）。
2. 增益只有 0.1 意味着**驱动能力很弱**。
3. 平移关节的运动方向一旦和重力方向不平行，重力就会**沿运动方向**产生一个持续阻力。
   机械臂水平时阻力为 0（能走）；一旦肩/肘抬起来让夹爪倾斜，阻力出现，
   这点驱动能力**完全推不动** → 关节不动 → 控制器判定"停住" → `ABORTED`。

**实测证据**（同一套代码，只改机械臂姿态）：

| 机械臂姿态 | 夹爪闭合结果 |
|---|---|
| 零位 `[0,0,0]`（臂竖直，夹爪朝上） | ✅ SUCCEEDED |
| 纯偏航 `[1.0,0,0]`（臂水平） | ✅ SUCCEEDED |
| **纯倾斜 `[0,-0.4,0.6]`** | ❌ ABORTED（关节纹丝不动） |
| **偏航+倾斜 `[0.5,-0.4,0.6]`** | ❌ ABORTED |

**解决方案：改用原项目的旋转夹爪结构（revolute + mimic）**，也就是本章 5.4 里写的那份代码：

- 关节从 `prismatic` 改成 `revolute`，用**绕轴旋转**代替平移；
- 关节轴放在指的根部、指沿 `+Z` 伸出，所以 0 位（张开）时重力矩为 0，
  旋转时重力表现为**绕轴力矩**而不是"沿运动方向的阻力"，量级小得多；
- 两指对称（左指 `<mimic multiplier="-1">`），重力矩天然互相抵消。

**改造后的实测结果**（同样跑那组倾斜姿态）：

| 机械臂姿态 | 闭合 −0.4 | 张开 0.0 |
|---|---|---|
| 零位 `[0,0,0]` | ✅ SUCCEEDED | ✅ SUCCEEDED |
| 纯倾斜 `[0,-0.4,0.6]` | ✅ SUCCEEDED | ✅ SUCCEEDED |
| 偏航+倾斜 `[0.5,-0.4,0.6]` | ✅ SUCCEEDED | ✅ SUCCEEDED |
| 小偏航 `[0.5,0,0]` | ✅ SUCCEEDED | ✅ SUCCEEDED |

关节实际值：右指 −0.4000，左指 +0.4000，对称联动全部正常。

**你要记住的两条经验**：

> **① "软件全绿但关节不动"时，去看物理** —— 控制器状态、接口归属、action 返回码都正常，
> 说明指令链路是通的，问题在"能不能推动"。
>
> **② 仿真里能用旋转关节就别用平移关节** —— 平移关节的运动方向和重力方向绑得太死，
> 而 Gazebo 的位置驱动能力又有限。原项目用旋转夹爪不是偶然，是踩过坑的选择。
